# Core Concepts

BolkAuth separates business logic from platform frameworks. The `@bolkauth/core` package contains the central authentication engine, session managers, password hashing algorithms, and adapter interfaces.

---

## ⚙️ Configuration Reference

The `createBolkAuth(config)` function accepts a `BolkAuthConfig` object:

```ts
interface BolkAuthConfig {
  adapter: BolkAuthAdapter;
  secret: string;
  session?: SessionConfig;
  email?: EmailConfig;
  emailAndPassword?: EmailAndPasswordConfig;
  socialProviders?: Record<string, OAuthProviderConfig>;
  social?: SocialConfig;
  onboarding?: OnboardingConfig;
}
```

### Options Breakdown

| Option | Type | Description |
|---|---|---|
| `adapter` | `BolkAuthAdapter` | Required database adapter (Drizzle, Prisma, or custom) |
| `secret` | `string` | Minimum 32-character secret key used for HMAC JWT signatures |
| `session.maxAge` | `number` | Session duration in seconds (default: 30 days) |
| `session.cookieName` | `string` | HTTP cookie name (default: `bolkauth.session`) |
| `emailAndPassword.enabled` | `boolean` | Enables traditional email/password registration and login |
| `emailAndPassword.minPasswordLength` | `number` | Minimum required password length (default: 8) |
| `socialProviders` | `Object` | OAuth provider credentials (GitHub, Google, etc.) |
| `onboarding.enabled` | `boolean` | Enables multi-step onboarding state persistence |
| `onboarding.requiredForAccess` | `boolean` | Automatically redirects users to onboarding before app access |

## 🔒 Session & Security Model

BolkAuth uses **stateless HTTP-only, SameSite Lax JWT cookies** backed by Web Crypto APIs (PBKDF2 with 100,000 iterations for passwords, HMAC-SHA256 for tokens).

### Authentication Lifecycle

1. **Sign-In / Sign-Up**: The user submits credentials to `/api/auth/sign-in/email` or `/api/auth/sign-up`.
2. **Password Verification**: Passwords are verified against stored PBKDF2 salt and hash strings (`salt:hash`).
3. **Token Creation**: A session record is created in the database, and a signed JWT containing `{ sessionId, userId }` is issued.
4. **Cookie Delivery**: The server returns a `Set-Cookie` header with `HttpOnly`, `SameSite=Lax`, and `Path=/`.
5. **Cross-Tab Synchronization**: Client-side state updates instantly across open browser tabs using the browser `BroadcastChannel` API.

## 🧭 Multi-Step Onboarding State Machine

BolkAuth includes a built-in onboarding engine. User progress is saved directly to user metadata records.

```ts
// Update current step
await fetch('/api/auth/onboarding/step', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ role: 'developer', teamSize: '5-10' }),
});

// Mark onboarding complete
await fetch('/api/auth/onboarding/complete', { method: 'POST' });
```

When `onboarding.requiredForAccess` is enabled, `bolkAuthMiddleware` automatically redirects un-onboarded users away from protected routes to `/onboarding`.
